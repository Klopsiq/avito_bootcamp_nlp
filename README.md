# Кандидатогенерация объявлений услуг Avito

Решение выбирает 50 объявлений для каждого запроса из `benchmark_queries.parquet`. Используются BM25 с географическими ветками, два текстовых энкодера и LambdaRank. Код работает локально, без внешних API.

Локальный Recall@50 = 0.8423367 на 55 428 dev-контекстах. Это локальная оценка, а не результат скрытого бенчмарка платформы.

## Воспроизведение отправленного результата

Требуется Python 3.12, CPU, около 8 ГБ доступной RAM и около 5 ГБ свободного диска с учётом окружения. GPU для инференса не нужен. Для точного совпадения используйте версии из `requirements.txt`; контрольная проверка выполнена на macOS ARM64. На иной архитектуре возможны различия вычислений с плавающей точкой, поэтому скрипт проверяет SHA-256 результата.

1. Получите исходные три Parquet-файла задания и положите их в `data/`. Они не включены в Git-репозиторий.
2. Скачайте [архив моделей и индексов](https://github.com/Klopsiq/avito_bootcamp_nlp/releases/download/v1.0/avito-d5-assets.tar.gz) и распакуйте его в корень репозитория. Появится папка `assets/` (архив 828 МБ): индексы, представления объявлений, энкодеры и обученные географические статистики. Для запуска нужен этот архив: он содержит дообученный RuBERT и индекс объявлений benchmark. Статистики IDF и размера локаций сохранены такими же, как при обучении на полном корпусе. Контрольная сумма архива указана в `reports/assets.json`.
3. Создайте окружение и установите зависимости:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

На macOS для LightGBM может потребоваться установленная библиотека OpenMP (`brew install libomp`). Установка зависимостей требует доступа к пакетному индексу; сам инференс работает офлайн.

4. Запустите:

```bash
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
python predict.py --data-dir data --assets assets --output answer.reproduced.csv
python validate_answer.py --data-dir data --answer answer.reproduced.csv
```

Скрипт читает признаки запросов, заново кодирует тексты, вычисляет кандидатов и признаки ранжирования, применяет модели и собирает CSV. Он не читает `answer.csv`, не использует таблицу сохранённых ответов и не обращается к внешним API. Представления объявлений используются как индекс корпуса. Поддерживается исходный корпус задания; при изменении корпуса индекс необходимо перестроить.

Ожидаемый SHA-256 итогового CSV:

```text
62adf643eb6ee88b81c8ee5d43c865960f81924bb8e79e77ad733a5d271e87f5
```

Повторный запуск дал байт-в-байт тот же CSV (отчёт `reports/reproduction.json`).

В `answer.csv` находятся 2452 строки и только колонки `query_id,answer`. Каждая строка содержит 50 уникальных идентификаторов из `benchmark_items.parquet`.

## Данные и признаки

Использованы `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet`. Пары из train дают положительные примеры; разметка бенчмарка недоступна и не использовалась. Для локальной проверки корпус состоит из 515 895 уникальных объявлений train и benchmark, чтобы не исключать известные положительные примеры. При построении ответа поиск ограничен 189 212 объявлениями benchmark.

Текст объявлений объединяет заголовок, параметры и описание. Текст запроса задаёт смысл поиска. `search_location_id`, локация и координаты объявления позволяют учитывать локальность услуги. Фильтры запроса и параметры объявления используются как признаки соответствия услуги и требований. Рейтинг и число отзывов дают дополнительные признаки; рейтинг не служит жёстким фильтром. Идентификаторы запросов не являются признаками моделей.

Ранжировщик получает 20 признаков: ранги и оценки каналов, BM25, покрытие слов с учётом IDF, совпадение локации, расстояние до центра поиска и наличие координат, длина запроса, размер локации, косинусная близость E5, покрытие заголовка, параметров и чисел, рейтинг и число отзывов, соответствие явно заданному рейтингу, взаимодействия косинусной близости с географией и покрытием слов.

## Алгоритм

1. BM25 с русским Snowball-стеммингом: глобальные и локальные кандидаты. При отсутствии объявлений в точной локации используется географический пул в пределах 100 км, с резервом минимум 200 ближайших объявлений. Центры поиска рассчитаны только по train-парам.
2. Дополнительный пул по обученной статистике переходов «локация поиска → локация выбранного объявления»: минимум 5 train-контекстов, максимум 8 локаций, до 90% наблюдаемой массы. Он применяется при отсутствии точной локальной выдачи.
3. Замороженный `intfloat/multilingual-e5-small`: masked mean pooling, L2-нормализация, размерность 384, длина 128 токенов, префиксы `query: ` и `passage: `. Косинусный поиск выполняется точно, без приближённого ANN. Глобальные и локальные ветки объединяются Reciprocal Rank Fusion, константа 60.
4. LightGBM LambdaRank: объединение 200 лексических и 200 семантических кандидатов; 160 деревьев, 15 листьев. Обучение на 5000 группах текстов из train; 4461 контекст с найденным положительным кандидатом, 673 831 строка. Сохраняются найденные положительные и до 150 случайных найденных отрицательных кандидатов. Положительные объявления искусственно в пул не добавляются. Выдача ранжировщика объединяется с BM25+E5 через RRF с весами 1:1.
5. Дообученный `cointegrated/rubert-tiny2`: размерность 312, длина 64 токена, masked mean pooling и L2. Обучен на GPU на 245 298 train-контекстах в течение двух эпох (3834 optimizer steps), batch 128, learning rate 2e-5, temperature 0.05. Используется контрастивное обучение с учётом нескольких известных положительных и глобальными/географическими отрицательными примерами. Тексты кодируются без префиксов E5.
6. Финальный RRF объединяет результат шага 4 и семантический канал обученного RuBERT с весами **1:0.5**, затем выбираются 50 объявлений.

Географические признаки влияют через выбор кандидатов и ранжировщик. Отдельный обученный слой GPS в RuBERT не используется.

## Локальная проверка

Разбиение выполняется по нормализованному тексту запроса (NFC, casefold, пробелы), а не случайно по строкам: все контексты одного текста попадают в одну часть. SHA-256 с seed 42 определяет train/dev/holdout в пропорциях 70/15/15. Получено 245 298 train-, 55 428 dev- и 53 737 holdout-контекстов. Holdout в выборе решения не использовался и остаётся непроверенным.

Контекст включает текст, локацию, доставку, фильтры и категорию. Recall@50 усредняется по контекстам; знаменатель содержит все известные релевантные объявления, а не только попавшие в пул кандидатов. В полном dev содержится 75 278 известных положительных пар. Веса выбирались на dev-пилоте из 2000 контекстов, после чего выполнялась проверка на полном dev. Полный dev включает пилот, поэтому его нельзя считать полностью независимой финальной тестовой оценкой.

| Решение | Полный dev Recall@50 |
| --- | ---: |
| BM25 + географические ветки | 0.77551 |
| BM25 + география + замороженный E5 | 0.81040 |
| BM25 + география + обученный RuBERT | 0.82752 |
| E5 + BM25 + LambdaRank | 0.83596 |
| Итоговый ансамбль с обученным RuBERT | **0.84234** |

Recall@200 составил 0.90759. Recall@50 с равным весом групп текстов составил 0.80745. Метрики и отчёты обучения сохранены в `reports/`.

## Анализ ошибок и исправления

- Случайное разбиение строк переносит одинаковые запросы между train и dev и завышает оценку. Использовано разбиение по группам текстов; статистики географии и параметры моделей обучались только на train.
- Жёсткая привязка к локации теряет релевантные объявления в соседних городах и при пустом локальном инвентаре. Сохранена глобальная ветка, добавлены координатный резерв и train-статистика переходов.
- Лексический поиск пропускает синонимы и перефразировки. Добавлены E5 и контрастивное дообучение RuBERT на предметной области.
- Семантическая близость сама по себе недостаточно учитывает фильтры, цифры и конкретный вид услуги. В LambdaRank добавлены покрытие параметров и заголовка, числовое совпадение и признаки рейтинга.
- 90.4% объявлений benchmark отсутствуют среди объявлений train. Решение использует признаки объявления и текста, а не запоминание частот item_id.
- Идентификаторы в BM25-индексе и семантическом индексе имеют различный порядок. Для совмещения используются явные отображения, проверяется соответствие ID, хешей модели и векторов.
- Импорт PyTorch и LightGBM в одном процессе приводил к аварийному завершению в локальном окружении. Кодирование запросов вынесено в отдельный процесс.

## Файлы и зависимости

- `predict.py`: самостоятельный инференс итогового решения.
- `encode_queries.py`: офлайн-кодирование запросов.
- `features.py`, `src/`: собственная реализация признаков, поиска, протокола, метрики и обучения.
- `models/ranker.txt`: обученный LambdaRank.
- `configs/inference.json`: зафиксированные веса и контрольная сумма.
- `validate_answer.py`: проверка формата и принадлежности ID.
- `reports/`: фактические отчёты обучения и проверки.
- `assets/`: отдельно распространяемый индекс и нейросетевые модели; исключён из Git.

Использованные библиотеки: NumPy, pandas, SciPy, scikit-learn, SnowballStemmer, PyTorch, Transformers, LightGBM, fastparquet, threadpoolctl. Исходные модели: [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) и [rubert-tiny2](https://huggingface.co/cointegrated/rubert-tiny2). Точные контрольные суммы моделей указаны в манифестах архива.
